## 1. 프로젝트 개요

### 1.1 배경 및 목적
개발자 취업 준비생은 여러 채용 공고에 동시에 지원하면서 지원 현황, 마감일, 전형 단계, 제출한 이력서·자소서 버전을 개인적으로 관리하기 어렵다. 기존 채용 플랫폼은 "구직" 중심이며, "내 지원 활동을 기록·분석하고 면접을 준비"하는 개인 관점의 도구는 부족하다.

본 프로젝트는 **개인 기록(personal tracking)** 을 중심으로,
1. 공공데이터/오픈API로 채용 시장 데이터를 수집·비교하고,
2. 로컬 LLM으로 면접 준비·문서 피드백을 제공하여,
취준 과정 전반을 한 곳에서 관리·분석할 수 있는 플랫폼을 개발하는 것을 목적으로 한다.

### 1.2 프로젝트 범위 (Scope)
- **포함:** 지원 기록 관리, 공고 URL 크롤링 자동 입력, 문서 관리, AI 면접/자소서 지원, 통계·시장 비교 분석, 알림
- **제외(이번 범위 아님):** 실제 채용 지원서 자동 제출(외부 채용 사이트 대행 지원), 기업↔구직자 매칭/중개, 결제·유료화, 모바일 네이티브 앱(웹 우선)

### 1.3 대상 사용자 (Persona)
| 구분 | 설명 |
|---|---|
| 주 사용자 | 취업/이직을 준비하는 개발자(신입~주니어) |
| 사용 맥락 | 여러 공고에 동시 지원, 지원 이력이 누적되며 추적이 필요한 상황 |
| 핵심 니즈 | "내가 어디에, 어떤 문서로 지원했고, 지금 어느 단계인지" + "어떻게 하면 합격률을 높일지" |

### 1.4 용어 정의
| 용어 | 정의 |
|---|---|
| 공고(Posting) | 채용 공고. 외부 URL 또는 공공 API에서 수집된 단위 |
| 지원(Application) | 사용자가 특정 공고에 지원한 기록 |
| 전형 단계(Stage) | 서류 → 코딩테스트 → 1차 면접 → 2차 면접 → 최종 등의 진행 상태 |
| 문서(Document) | 사용자가 업로드/관리하는 이력서·자기소개서 등 |
| 로컬 LLM | 외부 클라우드가 아닌 로컬 환경에서 구동되는 언어모델(예: Ollama 기반) |

## 2. 시스템 구성 및 기술 방향

### 2.1 권장 기술 스택 (참고용 제안)
| 구분 | 후보 |
|---|---|
| Frontend | React / Next.js |
| Backend | Spring Boot 또는 FastAPI / Node.js (팀 역량에 맞게) |
| DB | PostgreSQL / MySQL (관계형) + 필요 시 통계용 캐시 |
| 로컬 LLM | Ollama + 경량 모델(예: Llama 3.x, Qwen2.5, Gemma 등) / 임베딩 모델 |
| 크롤링 | requests + BeautifulSoup / Playwright(동적 페이지) |
| 파일 파싱 | PDF·DOCX 텍스트 추출(pdfplumber, python-docx 등) |

### 2.2 로컬 LLM 운영 방향
- 면접 질문 생성, 자소서 피드백, 직무 적합도 분석 등 **개인 문서를 다루는 기능은 로컬 LLM으로 처리**하여 개인정보 외부 유출을 최소화한다.
- 문서 텍스트는 청크 분할 후 임베딩하여 RAG 방식으로 활용 가능(예: 내 이력서 + 공고 요건 기반 질문 생성).
- 응답 지연을 고려해 **비동기 처리 + 진행 상태 표시**를 기본으로 한다.

## 5. 외부 인터페이스 요구사항 (공공데이터 / 오픈API)

> 아래는 활용 후보이며, 실제 사용 전 각 API의 신청·라이선스·요청 한도를 확인해야 한다.

| 분류 | 데이터/API | 활용 기능 |
|---|---|---|
| 채용정보 | **워크넷 채용정보 API**(한국고용정보원, 공공데이터포털) — 회사명·직종·근무지역·급여·마감일·채용정보URL 등 제공 | FR-APP-04, FR-ANL-03/04, FR-MKT-01/02/04 |
| 공통코드 | **워크넷 공통코드 API**(지역/직종/전공/자격 코드) | 데이터 정규화·분류 기준 |
| 직무/역량 | **NCS(국가직무능력표준)·워크넷 직무데이터/LOD** | 직무 적합도·역량 매핑(FR-AI-07, FR-MKT-02) |
| 공공기관 채용 | **잡알리오(공공기관 채용정보)** | 공공기관 공고 보강 |
| 기업정보 | **DART(전자공시) 오픈API** 등 기업 기본·재무 정보 | 기업 정보 조회(FR-MKT-03) |
| 공고 본문 | 사용자가 입력한 채용 공고 **URL 크롤링** | FR-APP-01 |

**연동 시 고려사항**
- 응답 포맷(XML/JSON), 일일 호출 한도, 페이지네이션 처리
- 수집 데이터는 주기적 배치로 적재 후 통계에 활용(실시간 호출 최소화)
- 출처 표기 및 재배포 제한 준수

## 7. 제약사항 및 가정
- **크롤링 한계:** 채용 사이트별 구조 상이·동적 렌더링·차단 가능성 → 주요 사이트 우선 대응 + 수동 입력 폴백 필수.
- **로컬 LLM 성능:** 팀 개발 환경 사양에 따라 모델 크기·응답속도 제약. 경량 모델 기준으로 품질을 검증한다.
- **공공데이터 갱신 주기:** 실시간이 아니므로 통계는 "수집 시점 기준"임을 UI에 명시.
- **개인 기록 중심:** 실제 지원서 자동 제출은 범위에서 제외.
