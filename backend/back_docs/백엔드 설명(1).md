## 1. 프로젝트 개요

**Plz-Job**은 개발자 취업 준비생을 위한 취업 공고·지원 이력 관리 + 채용 데이터 분석 플랫폼이다.

```
브라우저 (React localhost:5173)
    │  HTTP /api (HttpOnly 쿠키)
    ▼
Spring Boot (localhost:8080)
    ├── REST API (10개 컨트롤러, 39개 엔드포인트)
    ├── JWT + OAuth2 인증 (카카오 · 구글)
    ├── 파일 처리 (PDF/TXT 텍스트 추출)
    ├── Ollama LLM 클라이언트 (gemma3:4b)
    └── SSRF 방어 + 공고 크롤링 (사람인/잡코리아)
         │
         ├── Oracle XE 21c (docker:1522) ─ JPA/Hibernate
         └── Ollama (docker:11435)        ─ HTTP POST /api/generate
```

## 4. DB 스키마 — 테이블·컬럼 상세

> Oracle XE 21c, 서비스명 XEPDB1, 계정 plzjob  
> 모든 PK는 `NUMBER(19)` + Oracle 시퀀스 (`INCREMENT BY 50`, JPA `allocationSize=50` 일치)  
> 서비스 엔티티는 `BaseEntity` 상속 → `created_at / updated_at / deleted_at` 자동 포함  
> 분석 테이블(2개)은 ETL 전용 단순 구조 — BaseEntity 미상속

---

### 4-1. USERS — 사용자 계정

소셜 로그인(카카오/구글)으로만 가입·인증. 자체 비밀번호 없음.  
`(provider, provider_user_id)` 복합 UNIQUE 제약으로 동일 소셜 계정 중복 가입 방지.

| 컬럼 | Oracle 타입 | 제약 | 설명 |
|------|------------|------|------|
| `id` | NUMBER(19) | PK, SEQ_USERS | 내부 사용자 식별자. JWT의 subject(`sub`)로 사용되며, 모든 소유권 검증의 기준이 됨 |
| `provider` | VARCHAR2(20) | NOT NULL | 소셜 로그인 제공자. `KAKAO` 또는 `GOOGLE` (AuthProvider enum → 문자열 저장) |
| `provider_user_id` | VARCHAR2(100) | NOT NULL | 소셜 제공자가 발급한 고유 사용자 ID. 카카오: 숫자 문자열, 구글: sub 값 (21자리 숫자) |
| `email` | VARCHAR2(100) | NULLABLE | 소셜에서 제공된 이메일. 카카오 동의 항목에 따라 null일 수 있음. 로그인 식별에 사용하지 않음 |
| `nickname` | VARCHAR2(50) | NOT NULL | 화면 표시용 닉네임. 최초 가입 시 소셜 이름으로 자동 설정, 이후 프로필에서 수정 가능 |
| `desired_position` | VARCHAR2(100) | NULLABLE | 목표 직무 (예: 백엔드, 풀스택). 개인 vs 시장 비교(`/market/user-comparison`) 필터링에 활용 |
| `desired_region` | VARCHAR2(100) | NULLABLE | 목표 근무 지역 (예: 서울). 시장 분석 필터링에 활용 |
| `tech_stacks` | VARCHAR2(1000) | NULLABLE | 보유 기술 스택 목록. `List<String>`을 CSV로 저장 (예: `Java,Spring Boot,React`). `StringListConverter`가 변환 담당. 최대 약 50개 저장 가능 |
| `created_at` | TIMESTAMP | NOT NULL | JPA Auditing 자동 설정. 레코드 최초 INSERT 시각 |
| `updated_at` | TIMESTAMP | NOT NULL | JPA Auditing 자동 설정. 마지막 UPDATE 시각 |
| `deleted_at` | TIMESTAMP | NULLABLE | 소프트 삭제 시각. NULL이면 활성 계정. `@SQLRestriction("deleted_at IS NULL")` 적용으로 삭제된 행은 JPA 조회에서 자동 제외 |

**UNIQUE 제약:** `uq_user_social (provider, provider_user_id)`  
**시퀀스:** `SEQ_USERS INCREMENT BY 50`

### 4-2. JOB_POSTINGS — 채용 공고

사용자가 등록한 관심/지원 공고 정보.  
URL 입력 시 `JobPostingPreviewClient`가 사람인·잡코리아 페이지를 자동 파싱하여 필드를 채워준다.  
공고 등록 시 반드시 `APPLICATIONS` 레코드가 함께 생성된다 (1:1 관계).

| 컬럼 | Oracle 타입 | 제약 | 설명 |
|------|------------|------|------|
| `id` | NUMBER(19) | PK, SEQ_JOB_POSTINGS | 공고 내부 식별자 |
| `user_id` | NUMBER(19) | FK(USERS), NOT NULL | 이 공고를 등록한 사용자. 소유권 기준 컬럼. `JobPostingService.getDetail(userId, id)`에서 user_id 불일치 시 404 반환 |
| `company_name` | VARCHAR2(100) | NOT NULL | 회사명 (예: 카카오, 네이버) |
| `title` | VARCHAR2(200) | NOT NULL | 공고 제목. 크롤링 시 `og:title`에서 `[회사]`, `(D-N)`, `- 사람인` 패턴 제거 후 저장 |
| `url` | VARCHAR2(1000) | NULLABLE | 원본 공고 URL. 크롤링 소스 또는 직접 입력값. 같은 user_id에 대한 중복 URL 등록 방지 (`DUPLICATE_JOB_URL`) |
| `position` | VARCHAR2(100) | NULLABLE | 직무 분류 (예: 백엔드, 프런트엔드). 크롤링 시 7종 키워드 사전으로 자동 분류 |
| `region` | VARCHAR2(100) | NULLABLE | 근무 지역 (예: 서울 강남구). JSON-LD `jobLocation` 또는 한글 라벨 스캔으로 추출 |
| `start_date` | DATE | NULLABLE | 공고 시작일. JSON-LD `datePosted`에서 파싱. 상시채용 등 명시 없으면 null |
| `deadline` | DATE | NULLABLE | 공고 마감일. JSON-LD `validThrough`, og:description의 `마감일:YYYY-MM-DD` 패턴, 라벨 스캔 순으로 추출 시도. 상시채용이면 null |
| `tech_stacks` | VARCHAR2(1000) | NULLABLE | 요구 기술 스택 목록. CSV 저장. 크롤링 시 약 40종 기술 사전으로 키워드 매칭하여 자동 추출 |
| `description` | CLOB | NULLABLE | 공고 상세 내용. JSON-LD description, og:description, 사람인 `.jv_summary .freeform` 순 추출. 최대 4000자 트리밍. AI 면접질문 생성 시 최대 1500자 사용 |
| `favorite` | NUMBER(1) | NOT NULL, DEFAULT 0 | 즐겨찾기 여부. `boolean` → Oracle 1/0. `toggleFavorite(boolean)` 메서드로 토글 |
| `created_at` | TIMESTAMP | NOT NULL | 공고 등록 시각 |
| `updated_at` | TIMESTAMP | NOT NULL | 마지막 수정 시각 |
| `deleted_at` | TIMESTAMP | NULLABLE | 소프트 삭제 시각. 공고 삭제 시 연관 Application도 함께 소프트 삭제됨 |

**시퀀스:** `SEQ_JOB_POSTINGS INCREMENT BY 50`

### 4-3. APPLICATIONS — 지원 현황

공고(`JOB_POSTINGS`)에 대한 지원 상태를 추적하는 핵심 엔티티.  
`job_posting_id`에 UNIQUE 제약이 있어 **공고 1개 = 지원 1개** 관계가 강제된다.  
단계 변경 시 `changeStage()` 메서드 하나로 `current_stage` · `applied_at` · `final_result`를 일관되게 유지한다.  
생성 시 `histories`에 초기 이력(fromStage=null, toStage=INTERESTED)이 자동 삽입된다.

| 컬럼 | Oracle 타입 | 제약 | 설명 |
|------|------------|------|------|
| `id` | NUMBER(19) | PK, SEQ_APPLICATIONS | 지원 내부 식별자 |
| `job_posting_id` | NUMBER(19) | FK(JOB_POSTINGS), NOT NULL, UNIQUE | 연결된 공고. UNIQUE 제약으로 공고 하나에 지원 하나만 허용 |
| `user_id` | NUMBER(19) | FK(USERS), NOT NULL | 지원한 사용자. 소유권 검증 기준. AI 서비스 등에서 `app.getUser().getId().equals(userId)` 확인 |
| `current_stage` | VARCHAR2(20) | NOT NULL | 현재 지원 단계 (13종 `ApplicationStage` enum 문자열). 대시보드 집계·필터링의 핵심 컬럼 |
| `applied_at` | TIMESTAMP | NULLABLE | 실제 지원 시각. 월별 지원 추이 집계 기준 컬럼. INTERESTED/PLANNED 단계에서는 null. 공고 등록 시 `JobPostingCreateRequest.appliedAt`으로 직접 지정 가능하며, 미지정 시 APPLIED 단계 도달 시 자동 설정 |
| `final_result` | VARCHAR2(20) | NOT NULL | 최종 결과 (`FinalResult` enum). `changeStage()` 내부에서 자동 결정. 생성 시 기본값 `IN_PROGRESS` |
| `created_at` | TIMESTAMP | NOT NULL | 지원 레코드 생성 시각 (공고 등록과 동시에 생성됨) |
| `updated_at` | TIMESTAMP | NOT NULL | 마지막 단계 변경 시각 |
| `deleted_at` | TIMESTAMP | NULLABLE | 소프트 삭제. 공고 삭제 시 연동 삭제 |

**`changeStage()` 내부 `final_result` 자동 결정 규칙:**

| `to` 단계 | `final_result` |
|-----------|---------------|
| `FINAL_PASS` | `FINAL_PASS` |
| `DOCUMENT_FAIL`, `CODING_FAIL`, `INTERVIEW_FAIL` | `REJECTED` |
| `WITHDRAWN` | `WITHDRAWN` |
| 그 외 모든 단계 | `IN_PROGRESS` |

**시퀀스:** `SEQ_APPLICATIONS INCREMENT BY 50`

### 4-4. APPLICATION_STAGE_HISTORIES — 단계 변경 이력

지원 단계가 변경될 때마다 append-only로 쌓이는 이력 테이블.  
`BaseEntity` 미상속 — 수정/삭제 개념이 없고, `changedAt`은 생성자에서 `LocalDateTime.now()`로 고정된다.  
`Application` 생성자에서 초기 이력(fromStage=null, toStage=INTERESTED 또는 지정 단계)을 자동 삽입한다.

| 컬럼 | Oracle 타입 | 제약 | 설명 |
|------|------------|------|------|
| `id` | NUMBER(19) | PK, SEQ_STAGE_HISTORIES | 이력 내부 식별자 |
| `application_id` | NUMBER(19) | FK(APPLICATIONS), NOT NULL | 어느 지원 건의 이력인지 |

### 4-13. BaseEntity — 서비스 테이블 공통 컬럼

`BaseEntity`를 상속하는 엔티티(USERS, JOB_POSTINGS, APPLICATIONS, DOCUMENTS, DOCUMENT_VERSIONS, RECRUITMENT_SCHEDULES, RETROSPECTIVES, AI_GENERATIONS)에 아래 3개 컬럼이 공통으로 추가된다.

```java
@MappedSuperclass
@EntityListeners(AuditingEntityListener.class)
public abstract class BaseEntity {

    @CreatedDate
    @Column(name = "created_at", updatable = false)
    private LocalDateTime createdAt;      // INSERT 시 JPA Auditing이 자동 설정. 수정 불가

    @LastModifiedDate
    @Column(name = "updated_at")
    private LocalDateTime updatedAt;      // UPDATE 시 JPA Auditing이 자동 설정

    @Column(name = "deleted_at")
    private LocalDateTime deletedAt;      // NULL = 활성, 값 있음 = 소프트 삭제됨

    public void delete() { this.deletedAt = LocalDateTime.now(); }
}
```

**소프트 삭제 동작:**
- `service.delete()` → `entity.delete()` 호출 → `deleted_at = 현재 시각` → `save()`
- `@SQLRestriction("deleted_at IS NULL")` 어노테이션 → 해당 엔티티의 모든 JPA 조회(SELECT, JOIN)에서 삭제 행 자동 제외
- `APPLICATION_STAGE_HISTORIES`와 `APPLICATION_DOCUMENTS`는 BaseEntity 미상속 — 이력/연결 특성상 삭제 개념 불필요

## 6. 엔티티 설계 원칙

### 공통 패턴

```java
@Entity
@Table(name = "EXAMPLE")
@SQLRestriction("deleted_at IS NULL")   // 소프트 삭제 필터 (BaseEntity 상속 엔티티에 적용)
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)  // JPA용 기본 생성자, 외부 new 차단
public class Example extends BaseEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "example_seq")
    @SequenceGenerator(name = "example_seq", sequenceName = "SEQ_EXAMPLE", allocationSize = 50)
    private Long id;

    // setter 없음 — 의미 있는 비즈니스 메서드만 제공
    @Builder                             // 생성용
    public Example(...) { ... }
    public void update(...) { ... }      // 수정용 (null 체크 후 선택적 업데이트)
    public void delete() { super.delete(); }  // 소프트 삭제
}
```

### allocationSize=50 의미

JPA가 Oracle 시퀀스에서 ID를 한 번 조회하면 **50개를 메모리에 캐시**해 50번의 INSERT마다 시퀀스 조회 1회로 줄인다.  
→ Oracle 시퀀스도 반드시 `INCREMENT BY 50`으로 생성해야 PK 중복이 발생하지 않는다.

### StringListConverter — List\<String\> ↔ CSV

Oracle에 배열 타입이 없으므로 JPA 변환기로 처리한다.

```java
// 저장: ["Java","Spring Boot","React"] → "Java,Spring Boot,React"
// 읽기: "Java,Spring Boot,React" → ["Java","Spring Boot","React"]
@Convert(converter = StringListConverter.class)
@Column(name = "tech_stacks", length = 1000)
private List<String> techStacks = new ArrayList<>();
```

### enum 저장 방식

`@Enumerated(EnumType.STRING)` — DB에 `"INTERESTED"` 등 문자열로 저장.  
`EnumType.ORDINAL`(숫자)은 enum 순서 변경 시 의미가 달라지는 버그 위험이 있어 사용하지 않는다.

## 9. 인증 흐름 (OAuth2 + JWT)

### 9-1. 전체 5단계 흐름

```
① GET /api/auth/oauth2/kakao?redirectUri=http://localhost:5173/auth/callback/kakao
   → OAuthClient.buildAuthorizationUrl()
   ← { "authorizationUrl": "https://kauth.kakao.com/oauth/authorize?client_id=...&redirect_uri=...&response_type=code" }

② 사용자 브라우저에서 카카오 로그인 완료
   → 카카오가 redirectUri?code=XXXXX 로 리다이렉트

③ GET /api/auth/oauth2/kakao/callback?code=XXXXX
   → OAuthClient.fetchUserInfo("kakao", code)
       POST https://kauth.kakao.com/oauth/token     ← code → kakao_access_token
       GET  https://kapi.kakao.com/v2/user/me       ← 사용자 id, nickname, email 조회
   → UserRepository.findByProviderAndProviderUserId("KAKAO", "12345678")
       신규 사용자: User.builder().save() → isNewUser=true
       기존 사용자: 조회 → isNewUser=false
   → JwtProvider.createAccessToken(userId)    ← HS256, 30분 (1800초)
   → JwtProvider.createRefreshToken(userId)   ← HS256, 14일 (1209600초)
   → ResponseCookie("access_token", token).httpOnly(true).secure(false).path("/").sameSite("Lax").maxAge(1800)
   → ResponseCookie("refresh_token", token).httpOnly(true).secure(false).path("/").sameSite("Lax").maxAge(1209600)
   ← { user: {userId, nickname, provider}, isNewUser: true/false }

④ 이후 모든 보호 API 요청 → JwtAuthFilter (OncePerRequestFilter)
   resolveToken():
     1순위: "Authorization: Bearer TOKEN" 헤더
     2순위: 쿠키 "access_token"
   jwtProvider.isValid(token) → SecurityContextHolder.setAuthentication(userId)
   → @LoginUserId Long userId 컨트롤러 파라미터에 자동 주입

⑤ access 토큰 만료(30분) 후 → 프론트 axios 401 인터셉터 감지
   → POST /api/auth/reissue (refresh_token 쿠키 자동 전송, withCredentials=true)
   → authService.reissue(refreshToken) → 새 access+refresh 쿠키 발급
   → 원 요청 재시도
```

### 9-2. JwtProvider 핵심 코드

```java
@Component
public class JwtProvider {
    // jwt.secret 값으로 HMAC-SHA256 키 생성 (최소 256비트 = 32바이트 필요)
    private final SecretKey key;

    public String createAccessToken(Long userId)  { return create(userId, accessExpiration); }
    public String createRefreshToken(Long userId) { return create(userId, refreshExpiration); }

    private String create(Long userId, long exp) {
        Date now = new Date();
        return Jwts.builder()
            .subject(String.valueOf(userId))   // JWT subject = userId (Long → String)
            .issuedAt(now)
            .expiration(new Date(now.getTime() + exp))
            .signWith(key)                     // HS256 서명
            .compact();
    }

    public Long getUserId(String token) {
        return Long.parseLong(parse(token).getSubject());  // subject → Long 복원
    }

    public boolean isValid(String token) {
        try { parse(token); return true; }
        catch (JwtException e) { return false; }  // 만료·변조 모두 false
    }
}
```

## 12. 공고 미리보기 & SSRF 방어

### 12-1. URL 검증 4단계 (`JobPostingPreviewClient.validate()`)

```java
private URI validate(String rawUrl) {
    // 1단계: URI 파싱 가능 여부
    URI uri = URI.create(rawUrl.trim());
    // 실패 → INVALID_URL (400)

    // 2단계: scheme 검사 (http/https만 허용)
    String scheme = uri.getScheme();
    if (!"http".equals(scheme) && !"https".equals(scheme))
        throw new CustomException(ErrorCode.URL_NOT_ALLOWED);
    // file://, ftp://, javascript: 등 차단

    // 3단계: 도메인 허용목록 확인
    // 허용: saramin.co.kr, jobkorea.co.kr 및 그 하위 도메인
    // "evilsaramin.co.kr" 같은 접미사 위장 차단 (equals + endsWith("." + d))
    if (!isAllowedHost(host))
        throw new CustomException(ErrorCode.CRAWL_BLOCKED);  // 422: 수동 입력 안내

    // 4단계: SSRF 차단 (InetAddress DNS 조회 후 IP 범위 검사)
    InetAddress addr = InetAddress.getByName(host);
    if (addr.isLoopbackAddress()    // 127.0.0.1, ::1
     || addr.isSiteLocalAddress()   // 10.x, 172.16~31.x, 192.168.x
     || addr.isLinkLocalAddress()   // 169.254.x, fe80::
     || addr.isAnyLocalAddress())   // 0.0.0.0
        throw new CustomException(ErrorCode.URL_NOT_ALLOWED);
}
```

### 12-2. 공고 정보 파싱 우선순위

| 우선순위 | 방법 | 추출 가능 필드 |
|----------|------|-------------|
| 1순위 | JSON-LD (`script[type="application/ld+json"]`, `@type=JobPosting`) | title, company, region, startDate, deadline, description |
| 2순위 | OpenGraph 메타 (`og:title`, `og:description`) | title, company(bracket prefix `[회사]`), deadline |
| 3순위 | 한글 라벨 스캔 (`dt/th/strong/.tit/.label` 선택자) | 회사명, 마감일, 근무지역 |
| 4순위 | 키워드 휴리스틱 | techStacks(40종 사전), position(7종 분류) |

파싱 실패 필드는 `missingFields` 배열에 담아 반환 → 프론트가 수동 입력 UI를 표시.

## 13. 에러 처리

### GlobalExceptionHandler

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(CustomException.class)
    public ResponseEntity<ApiResponse<Void>> handleCustom(CustomException e) {
        ErrorCode ec = e.getErrorCode();
        return ResponseEntity.status(ec.getStatus())
               .body(ApiResponse.fail(ec.getCode(), ec.getMessage()));
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiResponse<Void>> handleValid(MethodArgumentNotValidException e) {
        // @Valid 검증 실패: 첫 번째 FieldError 메시지를 반환
        String msg = e.getBindingResult().getFieldErrors().get(0).getDefaultMessage();
        return ResponseEntity.status(422).body(ApiResponse.fail("VALIDATION_FAILED", msg));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiResponse<Void>> handleEtc(Exception e) {
        // 처리되지 않은 모든 예외 → 500
        return ResponseEntity.status(500)
               .body(ApiResponse.fail("INTERNAL_SERVER_ERROR", "서버 오류가 발생했습니다."));
    }
}
```

## 14. AnalyticsSeeder — Mock 데이터

ETL(Python)이 아직 미실행인 개발 환경에서 대시보드 차트가 빈 화면이 되지 않도록 앱 시작 시 자동으로 분석 Mock 데이터를 삽입한다.

```java
@Component
@RequiredArgsConstructor
public class AnalyticsSeeder implements CommandLineRunner {

    private final AnalyticsStackTrendRepository stackRepo;
    private final AnalyticsRegionJobRepository  regionRepo;

    @Override
    public void run(String... args) {
        if (stackRepo.count() > 0) return;  // 이미 데이터 있으면 스킵 (멱등성 보장)

        String m = YearMonth.now().toString();  // 예: "2026-06"

        // 기술 스택 추세 Mock (position='ALL': 직무 무관 전체)
        stackRepo.saveAll(List.of(
            AnalyticsStackTrend.builder().baseMonth(m).position("ALL")
                .stackName("Java").postingCount(1240).ratio(22.0).build(),
            AnalyticsStackTrend.builder().baseMonth(m).position("ALL")
                .stackName("Spring").postingCount(1100).ratio(19.5).build(),
            AnalyticsStackTrend.builder().baseMonth(m).position("ALL")
                .stackName("React").postingCount(980).ratio(17.4).build(),
            AnalyticsStackTrend.builder().baseMonth(m).position("ALL")
                .stackName("Kubernetes").postingCount(870).ratio(15.4).build()
        ));

        // 지역별 공고 수 Mock (sigungu='ALL': 시·도 합계 행)
        regionRepo.saveAll(List.of(
            AnalyticsRegionJob.builder().baseMonth(m)
                .region("서울").sigungu("ALL").postingCount(5200).build(),
            AnalyticsRegionJob.builder().baseMonth(m)
                .region("경기").sigungu("ALL").postingCount(2100).build(),
            AnalyticsRegionJob.builder().baseMonth(m)
                .region("부산").sigungu("ALL").postingCount(640).build()
        ));
    }
}
```

**`stackRepo.count() > 0` 멱등성 조건**: 서버 재시작을 반복해도 중복 삽입이 발생하지 않는다.  
ETL이 실제 데이터를 적재하면 count > 0 이므로 Seeder는 자동으로 건너뜀.  
`CommandLineRunner.run()`은 Spring ApplicationContext 초기화 완료 직후 실행된다.

## 16. 공통 응답 봉투 ApiResponse\<T\>

모든 REST 응답은 `ApiResponse<T>` 봉투로 래핑된다.

```java
public class ApiResponse<T> {
    private final boolean   success;     // 성공 여부
    private final T         data;        // 실제 응답 데이터 (에러 시 null)
    private final ErrorInfo error;       // 에러 정보 (성공 시 null)
    private final String    timestamp;   // KST (+09:00) 고정: OffsetDateTime.now(ZoneOffset.ofHours(9))

    public static <T> ApiResponse<T> ok(T data) { ... }   // 데이터 있는 성공
    public static ApiResponse<Void>  ok()        { ... }   // 데이터 없는 성공 (logout, delete 등)
    public static ApiResponse<Void>  fail(String code, String message) { ... }

    public static class ErrorInfo {
        private final String code;     // ErrorCode.code (예: "JOB_POSTING_NOT_FOUND")
        private final String message;  // ErrorCode.message (예: "공고를 찾을 수 없습니다.")
    }
}
```

### 성공 응답 예시

```json
{
  "success": true,
  "data": {
    "userId": 1,
    "nickname": "나현",
    "provider": "KAKAO"
  },
  "error": null,
  "timestamp": "2026-06-21T16:30:45.123456+09:00"
}
```

### 에러 응답 예시

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "LLM_PARSE_FAILED",
    "message": "AI 응답 형식을 해석하지 못했습니다."
  },
  "timestamp": "2026-06-21T16:35:12.456789+09:00"
}
```

**프론트엔드 axios 인터셉터 처리:**  
응답 인터셉터에서 `response.data.data`만 추출 → React Query가 `data` 필드만 받음.  
AI API는 LLM 응답 대기를 위해 `{ timeout: 120_000 }`을 별도로 지정 (기본 클라이언트 timeout=10,000ms).
